## 本机部署和配置

1. 在 Docker Desktop 启动后，从仓库根目录运行 `make portal-setup`。首次安装准备 Python 环境、数据库迁移、容器镜像和 OpenCode 基线。macOS 需要 GNU coreutils 的 `timeout` 或 `gtimeout`。准备至少 15 GB 可用磁盘，OpenCode 构建容器上限为 2.5 GB。
2. 展开 Portal 的「概览」，用终端打印的登录令牌连接 eval 工作空间。在同一页的「DeepSeek API Key」填写提供方密钥并保存，Portal 将配置写入本机 `.env` 并重启 LiteLLM。Docker Desktop 的用户级 socket 路径由启动脚本传入 Docker 包装命令，供会切换 `HOME` 的构建子进程使用。
3. 日常运行 `make portal-up`，检查 `make portal-status`。API 健康端点是 `/healthz`。本次确认 API、Worker、工作流和网关在线，版本列表包含 `2.3.0-sca.1`。运行日志留在 `.data/run/`，可用 `bash scripts/portal_demo.sh logs` 查看。
4. 修改架构页源文件后运行 `python3 Milestone/build.py`。Portal 从 `/portal/architecture` 使用生成页，从独立的静态入口加载事件映射和执行泳道脚本。安装 wheel 时也会携带生成页。页面源码更新后刷新浏览器，Python 活动变更由空闲 Worker 重启加载。

## 订单任务规格

订单任务在独立的本地 Git 示例仓库执行，起始提交为 `4972d711b5a52affa36c6f272d321196ded6b900`。任务开启自动拆分和拆分审核。每个子任务执行自己的 `unittest`，合并后用 `python -m unittest discover -s tests` 和 `python -m compileall -q orders` 验证全部模块。规则意图编译 `ruff.toml` 并在沙箱中检查。独立验收档案随任务登记，由另一份工作区运行 `python accept_orders.py`。

| 分支 | 主要职责 | 文件 |
| --- | --- | --- |
| `validation` | 校验订单 ID、币种、数量及整数分价格，拒绝布尔值和越界值 | `orders/validation.py` |
| `totals` | 按币种汇总数量乘单价，保留整数分计算 | `orders/totals.py` |
| `report` | 输出带表头、正确转义且保持输入顺序的 CSV | `orders/report.py` |

规划器校验文件范围。方案获批后，Temporal 启动三个并行子工作流，为各自准备工作区和 Docker 沙箱。三个 Agent 执行区间实际重叠。主工作流收集三个结果并装配，随后运行合并后的测试。独立验收横跨校验、汇总和 CSV，包含中文、逗号、引号、换行、零金额和输入不可变检查。

CI 用推送的精确提交运行。操作脚本从本地示例仓库导出提交，在断网只读容器执行 6 项单元检查，并验证 `CHANGELOG.md` 的 `Unreleased` 小节。脚本用 `/v1/tasks/{id}/ci-result` 回报该提交的判定。任务 Token 上限为 150,000，费用上限为 0.20 美元，最多两次验证后修正尝试。首跑的单轮超时设为 180 秒，重跑为 240 秒。

回放说明卡会随当前步骤更新。「解耦完成」（`#33`）展示三个子任务的职责、文件范围和并行关系。「沙箱已创建」（例如 `#43`）展示调度对象、镜像和沙箱名称。新沙箱事件记录运行驱动、工作区交付方式、CPU 与内存，早期事件用「当前环境」注明 Docker 配置来源。共享记忆（`#133`）解释已启用记忆的匹配范围、筛选策略和实际条数。命中内容会写入 `.sca/context/MEMORY.md` 供 Agent 参考。

图上的节点可以打开关联事件。说明卡的「查看原始事件」会暂停播放并展开证据。回放使用已有任务事件，实时视图通过事件流接收更新，定时刷新也会补齐数据。订单任务的 164 个回放步骤已逐项检查说明覆盖。
